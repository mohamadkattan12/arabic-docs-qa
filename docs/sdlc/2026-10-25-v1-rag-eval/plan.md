## Order of work
1. **Scaffold**: `uv init --app api`, `uv add fastapi uvicorn[standard] anthropic psycopg[binary]
   pgvector fastembed pymupdf python-multipart sse-starlette pydantic-settings`,
   `uv add --dev pytest pytest-asyncio httpx ruff mypy`; `pnpm create next-app web ...`; shadcn init.
   `docker-compose.yml` with `pgvector/pgvector:pg17`, `api`, `web`. → `docker compose up` shows all
   three healthy, `GET /health` → 200.
2. **DB + migration**: `001_init.sql` (tables, HNSW + GIN indexes), applied at startup. Test:
   migration is idempotent (apply twice → no error).
3. **Chunking + ingest**: Markdown split by headings (location = section heading), PDF via PyMuPDF
   per page (location = "page N"), ~800-token chunks with overlap; sha256 dedupe; embed with
   fastembed (model from env). Tests: chunk boundaries, Arabic text survives, re-ingest = no new rows.
4. **Corpus**: write the fictional docs; render the Arabic PDF fixture. Startup loads corpus when DB empty.
5. **Retrieval**: vector top-k + FTS (`arabic`/`english` by detected language) + RRF. Tests on a
   seeded test DB: known question returns expected chunk in top 6, for one AR and one EN case.
6. **Answer**: `claude_client.py` wraps `anthropic` SDK (`messages.stream`, adaptive thinking,
   explicit effort, refusal fallback, stop-reason checks, prompt-cached system prompt). Chunks sent as
   `search_result` blocks with `citations.enabled`; citations mapped by `search_result_index`
   back to chunk ids. "Not found" sentinel → `answerable=false`. Tests with a fake client
   (recorded response shapes): citation mapping, not-found path, refusal path, max_tokens path.
7. **Routes**: `/ask` (SSE), `/documents` (upload validation 413/415, list, delete), `/eval/latest`,
   CORS. Tests via `httpx` ASGI client.
8. **Eval**: `dataset.jsonl` (~40 cases incl. 3 injection), `run.py --models ...`, judge rubric,
   report (JSON + Markdown, recommended-model rule). Unit test the metric math and the
   recommendation rule on fixed fake results (no API calls).
9. **Web**: Ask page (streaming, citation chips, `dir="auto"`), Documents page, Eval page.
   Loading / empty / error states. Check in the browser (screenshots AR + EN).
10. **CI**: `.github/workflows/ci.yml` (Postgres service with pgvector; backend + frontend jobs).
11. **Run the real eval** (needs Mohamad's API key, costs a few dollars; ask before running),
    commit results, write README (pitch, GIF/screenshot, architecture diagram, run steps, eval
    table, recommended model, design decisions, "local only" warning).
12. **Verify, review, PR**: verifier + reviewer subagents; create the public GitHub repo
    `mohamadkattan12/arabic-docs-qa` (ask before publishing); PR from `v1-rag-eval` to `main`.

## Risks
- **Arabic FTS quality**: Postgres `arabic` stemmer is basic. Mitigation: hybrid with vectors; eval
  measures hit@6 for Arabic separately. Rejected: Elasticsearch/OpenSearch (heavy for a demo).
- **Embedding model download (~2 GB)** slows first start and CI. Mitigation: model cached in a Docker
  volume; CI tests use a tiny fake embedder (deterministic hash vectors) so CI never downloads it.
- **Citation mapping is the riskiest logic** (`search_result_index` → chunk). Covered by unit tests
  with recorded response shapes.
- **SSE through Next.js**: browser calls the API directly (CORS) instead of proxying, to avoid
  buffering. Rejected: Next.js route-handler proxy (adds buffering risk, more code).
- **Eval cost/flakiness**: LLM-judged scores vary run to run. Mitigation: deterministic metrics carry
  the headline; judge score reported alongside; dataset and judge prompt versioned in git.
- **Secrets**: `.env` git-ignored from the first commit; pre-publish check with `git grep -n "sk-ant"`.

## Departures from plan
- Step 1: `uv init --app` generated a packaged `src/api/` layout, so the backend package is
  `api` (`src/api/main.py`, imported as `api.main`) instead of `app/`. Eval stays at `api/eval/`.
- Step 1: web `typecheck` script is `next typegen && tsc --noEmit` (Next 16 generates the global
  `LayoutProps`/`PageProps` types; plain `tsc` fails without them). Proof/CI use `pnpm typecheck`.
- Step 1: `next.config.ts` uses `output: "standalone"` for a small Docker image (per Next docs).
- Step 2: Postgres is published on 127.0.0.1:5434 (5432/5433 are taken on the dev machine);
  tests create and drop a `docsqa_test` database there (`TEST_ADMIN_DATABASE_URL` overrides it).
- Step 2: chunks store `fts_config regconfig` and a generated `tsv` column, so full-text search
  uses each chunk's own language config. Startup fails with a clear message if the stored
  embedding dimension differs from the model's.
- Step 3: the embedding dimension comes from the model (`TextEmbedding.embedding_size`), so there is
  no separate dimension setting. `FastEmbedder` adds e5's `query: `/`passage: ` prefixes (fastembed
  does not). Paragraph-grouped chunks have no overlap; overlap applies only when one paragraph is
  hard-split (a paragraph boundary is already a clean break). Model cached in a `models` volume;
  first start took 2m41s. Real-model check: Arabic leave question ranks AR leave > EN leave > expenses.
- Step 4: corpus is 8 docs (4 AR, 4 EN) for the fictional "Mithal Co." with deliberately unusual
  numbers (e.g. 27 days annual leave) so the eval tests retrieval, not model prior knowledge. Loaded
  at startup from a read-only `./corpus` mount (40 chunks with the real model).
- Step 4 finding (spec concern 1, measured): the Chrome-rendered Arabic PDF fixture extracts with
  lam ligatures scrambled ("اإلجازات" for "الإجازات", "املوظف" for "الموظف"). PyMuPDF flags
  (no-ligatures, dehyphenate, sort) do not fix it, and a find-and-replace fix is unsafe because "ال"
  is the normal definite article. Kept as an eval case; README will recommend .md/.txt for Arabic.
  Fixture is reproducible with `scripts/make-pdf-fixture.sh`.
- Step 5 (spec amended, Mohamad chose option 1): default retrieval is vector-only; hybrid stays as
  `RETRIEVAL_MODE=hybrid`. Real-model measurement, 10 questions (5 cross-language), expected section
  in top 6: hybrid 6/10 (same-language 5/5, cross-language 1/5), vector 10/10 (all rank 1 but one
  rank 2). FTS weights 0.5 and 0.3 gave the same 6/10. Full-text query uses OR of lexemes
  (`plainto_tsquery` with `&` replaced by `|`) in both Arabic and English configs.
- Step 1: embedding model confirmed in fastembed: `intfloat/multilingual-e5-large` (dim 1024, 2.24 GB).
